### Chloe C1 — Small read-only readiness checker

Original B6 / roadmap DA8. Implement only `analytics/integration_check.py` and its test file. This can finish while Eric changes the reducer because it consumes the frozen APIs.

Proposed command, **available only after C1 is implemented**:

```sh
.venv/bin/python -m analytics.integration_check --session-id 2026-10-18T05-14-03_sahil_djin_vs_kaz
```

Requirements:

- Read `KUMITE_BRAIN_URL`, `KUMITE_REPLAY_URL` and `KUMITE_ANALYTICS_URL`, defaulting to localhost ports 8765, 8766 and 8767. Check all three `/health` responses and the requested analytics `/stats/{id}` and `/learning/{id}`. Verify response identity and basic structure; distinguish missing session, unavailable data and unreachable service.
- Default mode reports a healthy **snapshot**, not proof of live writes. Add `--watch-seconds`, `--poll-seconds`, `--timeout-seconds` and `--require-advance`. Bound requests and total observation time; use monotonic deadlines. No new dependency is needed.
- In advance-required mode, compare round identifiers in stats and learning with the initial snapshot. Require a later completed round in both within the observation window, allowing their flushes to arrive separately. Do not require every damage/rate value to grow. An idle/static recording can be healthy without satisfying advancement. A reset or session mismatch must not count as advancement.
- Print a concise summary; `--json` provides the same outcomes in machine-readable form. Use exit 0 for requirements satisfied, 1 for failed/unusable responses, and 2 for an otherwise healthy session whose required advancement timed out. Missing learning after the allowed wait is incomplete, not a measured zero. Do not infer Sentry environment, database use or Windows compatibility from `/health`.
- Make only GET requests. Do not start/stop services, change files/configuration, trigger analysis, upload telemetry or display credentials. Include bounded, credential-free diagnostics.

Done when tests using local stub HTTP responses or a local test server cover all-healthy, one service unavailable, malformed response, 404/503, alternate base URLs, unchanged data, delayed learning catch-up, valid round advance and timeout. No game installation, new insight fields, live cloud access or app automated tests are needed. Eric runs the actual host check and owns the runbook.
